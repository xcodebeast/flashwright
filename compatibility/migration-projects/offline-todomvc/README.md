# Offline TodoMVC application corpus

This corpus preserves every file in Playwright 1.60.0's `examples/todomvc/tests` directory: 23 assertion tests, one recording seed and their shared fixture. Test bodies remain byte-for-byte upstream sources. The seed contributes one runner case but no application assertions.

The application is the TypeScript React implementation from `tastejs/todomvc` at `ff43b02e59dfa604386bb382034b2cd07c2bcd8a`. Its HTML, JavaScript and CSS are retained without edits. `provenance.json` records immutable source URLs, byte counts and SHA-256 hashes for each test, asset and license. `licenses/` retains TodoMVC, bundled component and Playwright notices; bundled source comments also remain intact.

The local HTTP server applies six declared attribute additions to the application bundle: three test IDs and three accessible labels. The resulting bundle matched the public Playwright demo bundle byte-for-byte when imported. These adaptations support the original tests without changing application logic. The original HTML resolves the pinned assets at their original paths; it has no public demo banner. The CSS uses embedded SVG data URLs and needs no remote assets.

Generated test fixtures adapt the package import through an engine adapter and replace the public demo URL with the loopback HTTP address. All 24 test bodies stay unchanged. Migration therefore requires package imports and a fixture URL adaptation. The server serves actual application files over HTTP and uses no interception or replay.

Run `bun tools/run-application-suite.mjs NEW_OUTPUT_DIRECTORY` with explicit `FLASHWRIGHT_BROWSER_PATH` and `FLASHWRIGHT_DRIVER_PATH` after building the checkout. Bun is the default runner runtime; `FLASHWRIGHT_APPLICATION_RUNTIME` selects an absolute alternative runtime path. Both engines execute all cases with one worker, no retries and the same browser, viewport and artifact settings. Flashwright's private upstream browser/request backends are disabled in the generated config and worker fixture adapter.

The receipt retains every runner outcome and diagnostic, generated source hashes, request counts, binary/dependency/source identities and watchdog cleanup. Any failure leaves application admission false and exits nonzero. This is functional evidence using installed development packages. Comparative performance, packed-package application admission, other representative apps and native Linux remain open.

Recheck schema-2 receipts with `bun tools/verify-application-suite.mjs RETAINED_DIRECTORY` from the recorded source checkout and dependency installation. The verifier reconstructs generated adapters, configuration and fixture/test bytes, checks the complete retained-file inventory and referenced attachments, rederives test identities from the pinned declarations, and recomputes outcomes from raw reports and requests. Actual failed or timed-out runner tests remain gap evidence; skipped/interrupted attempts, retries, watchdog intervention and surviving processes reject complete-corpus verification. A successful verifier exit confirms the recorded outcomes even when application admission remains false. Older schema-1 diagnostic receipts require a fresh run; do not relabel them.

Run `bun test ./tools/test-application-corpus.mjs ./tools/test-application-suite-contract.mjs` for corpus integrity, HTTP serving and outcome-corruption checks. The stricter contract was also replayed against the first real reports without launching new browsers. A fresh schema-2 collection, full standalone verification and normalized public snapshot are now retained in the [application checkpoint](../../evidence/application-checkpoint-2026-10-10.json). The native build from ca1fb020 again passed Playwright 24/24 and Flashwright 23/24; the recorded source checkout is required for independent replay.

The initial development probe passed 24/24 cases on Playwright and 23/24 on Flashwright. Flashwright explicitly rejected `expect.toMatchAriaSnapshot` in `deleting-todos/should-clear-all-completed-todos.spec.ts`; the complete case remains in the corpus. That means 22 of the 23 assertion tests passed on Flashwright, plus the recording seed. Fresh receipts determine the current outcome as engine support changes.
