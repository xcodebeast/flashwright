# Local Download development checkpoint

This snapshot verifies common local Chromium downloads on native macOS arm64 with Bun 1.4.2 and pinned Playwright 1.60.0/Chrome 148.0.7778.96. The [checkpoint](../downloads-checkpoint-2026-10-10.json) binds the implementation, driver, browser and retained evidence. It is experimental coverage, with no release or speed claim.

The four plain/traced engine runs contain 52 shared outcome checks and four separately asserted stream-close differences. They cover all nine Download methods, download events/predicates, normal-context policy, cancellation, deletion, saved copies, original Page identity, same-process iframe downloads and binary/Unicode data. The 156-group core run includes packed ESM/CommonJS library and runner consumers and the three preserved TodoMVC tests. Controlled stream ownership checks pass on Bun and Node 22/24 using identical compiled JavaScript.

After context closure, the pinned reference can reject asynchronously inside its stream `_read` and leave consumption pending. Flashwright deliberately reports an observable `TargetClosedError`. The differential records this separately; it is neither equal-outcome conformance nor a speedup. The pinned reference archives omit Download calls, while Flashwright records additional metadata for its six asynchronous methods. The trace verifier checks 26 archives; two actual pinned viewer cases render success/error details without page errors. Context-close-active is tested without tracing; other archives finalize before context teardown.

Native lifecycle cases retain physical filesystem ownership after asynchronous cancellation and browser exit, withdraw queued expired work, wait for started copies during context close, and release guardian cleanup after driver death. Metadata and active file jobs are bounded. There is no hard disk-byte quota, atomic-copy claim, or exhaustive publication-race coverage.

`development-attempts` preserves earlier failures and partial results. SVGOMG currently passes six of six preserved tests on Playwright and five of six on Flashwright: its download test passes, while open-svg evaluation in an out-of-process frame remains unsupported. Native Linux, remote/persistent contexts, popup fallback, broader consumers, fresh matched performance and release gates remain open.

To regenerate, follow the repository setup instructions with Bun 1.4.2 and set `FLASHWRIGHT_BROWSER_PATH` to the pinned full Chromium executable. Run `bun tools/verify-core.mjs` for the complete verification. Focused Download checks are `bun tools/test-downloads.mjs <new-directory>`, `python3 tools/verify-download-traces.py <new-directory>` and `bun tools/test-download-viewer.mjs <new-directory>` after building the driver and packages. `bun tools/test-download-host.mjs <new-directory>` runs controlled stream checks; the same script accepts the pinned Node runtimes.

The export manifest records original and exported file hashes. Normalization changes workstation paths and dependent report/log hashes while preserving every numeric, boolean and null observation. Raw trace ZIPs and viewer screenshots remain private at recorded hashes; regeneration creates new artifacts with new identities. Download differential/viewer watchdog reports record clean observed-process exit. The complete core run had no outer watchdog; individual checks retain their own supervision.
