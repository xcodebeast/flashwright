# Bounded early renderer-retirement recheck

This private patch applies to the recovered Linux Chromium foundation at `8625e066febc721e015ea99842da12901eb7ed73`, with the source composition recorded in [the recovery checkpoint](recovered-linux-2026-10-21/README.md). It is not an upstream-only patch or a selected public default.

`FlashwrightRetirementWaitAudit` records completion-only polling counts and retirement phase intervals. `FlashwrightEarlyRetirementRecheck` changes only the first delayed check from five milliseconds to 250 microseconds. Both features default off. The original service-context and Blink completion predicates, short-circuit order, retained context, moved callback, five-second deadline, memory collection and observer cleanup remain. Every subsequent retry remains five milliseconds. Nominal checks become 0, 0.25, 5.25, 10.25 ms; slow readiness can therefore finish slightly later than with the original schedule. Existing readiness-before-deadline precedence is unchanged.

The [retained screen](../../benchmarks/results/early-retirement-recheck-linux-2026-10-21.json) includes 60 attribution contexts, 60 candidate diagnostic contexts, 28 worker-control contexts and 1,980 unchanged setup test outcomes. Warm close improves about 40% in both diagnostic orders. Complete 240-test setup improves 13.6–15.4% at one worker and remains approximately unchanged at four. The declared all-worker 10% gate fails. No application expansion, adoption or final performance claim follows.

Worker controls cover immediate construction, acknowledged idle/busy/nested/shared/service workers, explicit termination and fresh successor state. Busy-worker retirement still takes about two seconds in both arms, and an enabled service case uses the slower fallback. They do not force all native startup/shutdown races; no new native unit matrix was run. Timing runs disable audit logging. The original source and byte-identical rebuilt baseline executable are restored.
