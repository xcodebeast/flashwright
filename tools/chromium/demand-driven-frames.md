# Private speculative-frame subscription probe

This unadopted patch targets the classic Chromium scheduler at revision `8625e066febc721e015ea99842da12901eb7ed73`, on the existing private renderer-reuse/early-idle/lazy-VAAPI composition. See the [Linux setup screen](../../benchmarks/results/demand-driven-frames-linux-2026-10-21.json).

`FlashwrightDemandDrivenUncappedFrames` is disabled by default. With uncapped frames, it suppresses three proactive subscription reasons: a pending main frame, a recent draw attempt and a no-update commit. It requires the asynchronous multi-threaded classic mode and excludes synchronous, single-threaded, full-pipeline and SlimScheduler configurations. Actual main-frame/redraw/invalidation/video demand, pending trees, tile preparation, smoothness priority, acknowledgements and frame-history flags remain intact. Unlike the pacing probe, it introduces no timer delay.

The native gate passes 547 checks: 525 existing cases and 22 added enabled-policy/mode-guard cases. Tests verify actual observer removal followed by asynchronous commit-triggered readdition and drawing, including production main-frame-before-commit settings. Nine initial checks fail against the original source. Eight later failures were incorrect expectations in new reentrant-draw tests: delivered demand may wait unsubscribed, whereas repeated failed draws can leave another real request requiring subscription. Corrections preserve the original tests and strengthen dispatch/progress checks. An explicit SlimScheduler exclusion case was added after the browser screen; all 547 checks pass again without changing production source.

Both browser arms pass six motion/storage/rAF/pixel control contexts, 60 preflight tests and 1,920 timed tests using the unchanged setup body. Complete time improves 0.5% / 0.6% at one worker and 7.5% / 9.0% at four workers. Charged CPU falls 4.2–4.6% and 7.7–8.0%, respectively. These observations miss the prospective 10% elapsed improvement in every cell and 20% four-worker CPU improvement. No application expansion or adoption follows. The exact baseline source and browser executable are restored.

Further enabled-policy tests would be required for no-update-history/invalidation interactions, frame-sink loss, shutdown recovery, complete drainage after repeated failed draws, media/scroll/worklets and trace artifacts. The passing existing tests mostly exercise feature-off behavior. Retain these gaps and every failed attempt; this experiment does not establish broad scheduling parity, final resource admission or the 2× objective.
