// How it works

Where the time goes

Flashwright changes only where Playwright spends time. Playwright's own test suites are the regression bar.

01

Warm browsers, fresh contexts

Each test gets a new tab in a context the worker keeps, with everything a test can change reset in between.

02

Waits that react to the page

Actions and assertions re-check when the page changes, not on a backoff timer.

03

Input without frame waits

Clicks don't wait for animations to settle. The hit-target check still runs.

04

Workers started early

Workers and browsers launch while the config is still being read. The longest tests start first.

05

A faster start

A V8 code cache, lazy loading and fewer browser round trips per action.

06

Faster screenshots

Same pixels, faster encoding, and baselines byte-identical to Playwright's.

// Options

Fast by default, Playwright on request

Every default that changes behavior is a typed option. Turn Playwright's behavior back on per project, file or describe block.

playwright.config.ts
export default defineConfig({
  testOrder: 'file',
  use: {
    isolation: 'strict',
    waitForAnimations: true,
    failFastWhenIdle: false,
  },
});
OptionDefault
isolation'recycled' · a new tab in a reset context per test
failFastWhenIdletrue · fail once nothing can change the page
waitForAnimationsfalse · don't wait for moving elements
testOrder'longest-first' · slowest tests start first
locatorPolicy'any' · 'test-id' allows only getByTestId()

More, like workersPerProcess, preloadPages, instantAnimations and blockResources, in the README.

// Questions

Before you switch

Do I have to change my tests?

No. Imports, configs and npx playwright commands stay as they are. Browsers, reporters, the trace viewer and the VS Code extension are Playwright's.

What behaves differently?

Contexts are recycled, pointer actions don't wait for animations, idle assertions fail early, and the longest tests run first. Each has an option to restore Playwright's behavior. The README lists every difference.

Which browsers get faster?

Mostly Chromium. Firefox and WebKit keep Playwright's behavior, apart from reusing one tab per worker. Flashwright runs Playwright's own browser builds.

How do I know nothing broke?

Playwright's own test suites are the bar: tests/page passes 2610/2610 on Chromium, and the runner, library and MCP suites match pristine Playwright 1.64.1.

How do I go back?

npm i -D @playwright/test@1.64.1. Nothing in your code refers to Flashwright.
