Where the time goes

Flashwright changes only where Playwright spends time, and keeps its observable behavior. Playwright's own test suites are the regression bar.

Warm browsers, fresh contexts

Each worker keeps one browser context and gives every test a brand-new tab in it, after resetting everything a test can change: cookies, storage of every origin, caches, routes, permissions, clock and more.

Waits that react to the page

Actions and assertions re-check as soon as the page changes instead of after a 20–500 ms backoff. An assertion that can no longer pass fails right away.

No frame waits before input

Clicks, hovers and drags don't wait for animation frames or for moving elements to stop. Playwright's hit-target check still makes sure the element receives the input.

Workers ready before they're needed

Worker processes and their browsers start while the CLI is still reading the config, a spare stands by once tests fail, and the longest tests start first.

A faster start

A V8 code cache for Playwright's own bundles, lazy loading of what a run doesn't use, fewer browser round trips per action, page scripts the browser compiles once.

Faster screenshots

Speed-optimized PNG encoding with the same pixels, and pixel comparison with fast paths for toHaveScreenshot(), whose baselines stay byte-identical to Playwright's.

Made for agents that check their own work

Coding agents re-run the same test after every edit. Outside CI, the first playwright test starts a warm session that keeps the runner, workers and browsers ready for the next run.

Speed by default, Playwright's behavior on request

Every speed default is a typed option. A project, file or describe block can turn Playwright's behavior back on, or ask for even less work.

// playwright.config.ts: Playwright's behavior, for a suite that relies on it
export default defineConfig({
  testOrder: 'file',          // run tests in Playwright's order
  use: {
    isolation: 'strict',      // a new browser context for every test
    waitForAnimations: true,  // wait for elements to stop moving before input
    failFastWhenIdle: false,  // let failing assertions wait out their timeout
  },
});

// a file or describe block that needs less
test.use({
  instantAnimations: true,                     // CSS and Web Animations end within a frame
  blockResources: ['image', 'font', 'media'],  // never load these
});

isolation'recycled'A new tab in a reset context per test. 'strict' gives every test a new context, like Playwright.
failFastWhenIdletrueAn assertion fails once nothing can change the page before its timeout.

Questions

Do I have to change my tests?

No. Flashwright is published as the packages that stand in for Playwright's, so @playwright/test imports, playwright.config.ts and npx playwright commands stay as they are. Browsers, reporters, the trace viewer, codegen and the VS Code extension are Playwright's.

What behaves differently from Playwright?
  • Tests get a fresh tab in a recycled, fully reset context instead of a new context (isolation: 'strict' restores Playwright's).
  • Pointer actions don't wait for moving elements to stop (waitForAnimations: true).
  • Assertions on an idle page fail before their timeout (failFastWhenIdle: false).
  • With several workers, the longest tests start first (testOrder: 'file').
  • Outside CI, a warm session keeps browsers for up to 5 minutes after a run (FLASHWRIGHT_SESSION=0 turns it off).
  • Screenshot files have identical pixels but are larger PNGs; toHaveScreenshot() baselines are unchanged.
Which browsers does it speed up?

Most of the gains are on Chromium. Firefox and WebKit keep Playwright's behavior apart from reusing one tab per worker (TodoMVC on Firefox: 6520 → 3868 ms) and the options that apply to them. Flashwright runs Playwright's own browser builds: there is no custom browser to install or trust.

How do you know nothing broke?

Playwright's own test suites are the bar, compared with pristine Playwright 1.64.1 on the same machine: tests/page passes 2610/2610 on Chromium; the test runner, library, MCP, Electron and extension suites match pristine Playwright.

How do I go back to Playwright?

npm i -D @playwright/test@1.64.1. Nothing in your code refers to Flashwright, so that's the whole change.

Is this an official Playwright project?

No. Flashwright is an independent fork of Playwright and is not affiliated with or endorsed by Microsoft. It is Apache-2.0, like Playwright.
